# 信息发布与网站服务需求

## 1. 文档目的

本文是 `jilinjobs-cms` 当前“信息发布与网站服务”业务需求基线，用于约束中心主站的 CMS 通用模型、公开网站、管理端、初始化数据、历史迁移与当前迭代范围。

当前网站参照基线为“吉林省高等学校毕业生就业信息网”。`www.jilinjobs.cn` 因上级统一规划跳转到 `24365.jl.smartedu.cn`；在需求分析、页面结构分析、视觉取证和内容采集过程中，两者视为同一原网站。其他域名原则上视为外部网站或外部系统。

V4.2 在 V4.1 基础上吸收 2026-08-29 Human Admin Review 结论：CMS 后台优先采用通用、可扩展且可复用的业务模型；公开站稳定布局与一次性集成仍属于工程资产，不机械追求“零硬编码”；导航位置独立建模；网站配置收敛为通用网站属性；轮播/友情链接等使用通用列表；首页招聘活动横幅使用广告位；当前阶段不实现认证授权和不同权限下的功能限制，只记录未来权限规划。

## 2. 建设目标

当前主站目标仍为：

> **现网视觉与布局复刻 + 必要技术适配 + 可持续运营的通用 CMS 能力。**

具体目标：

1. 以原网站页面结构、主要布局关系、菜单/栏目结构和视觉识别作为新版公开站基准；
2. CMS 后台优先提供栏目、文章、页面、页面组、导航、通用列表、广告位、网站属性、静态资源等通用业务能力；
3. 公开站负责固定页面结构、布局、视觉和稳定工程集成，通过 CMS 业务数据驱动需要运营维护的内容；
4. 不为了“可配置”而把稳定、一次性、基本不需要运营调整的工程设计强行配置化；
5. 使用 Vue / Spring Boot 重建，不复制旧网站前端代码；
6. 站点结构与确定内容形成可重复初始化基线，测试数据与站点基线分离；
7. 原站历史运营内容通过独立迁移机制处理，不混入 Flyway 初始化数据。

## 3. 当前范围

### 3.1 In Scope

- 中心主站公开前台；
- CMS 管理端；
- 栏目、文章、固定页面、页面组；
- 导航位置与多级导航条目；
- 通用列表与列表项；
- 广告位与广告内容；
- 网站属性；
- 网站静态资源管理；
- 固定首页模板及数据驱动内容；
- 固定公开 URL、alias 与 canonical URL；
- 初始化数据库基线与初始化静态资源包；
- 现网视觉与布局复刻；
- 响应式、浏览器兼容和基础搜索引擎友好；
- 可识别历史内容地址的迁移映射原则。

### 3.2 当前暂不实现

- “中心党建”红色主题内容和党建专属后台能力；主导航保留占位；
- 慧就业招聘信息、直播课程的真实 iframe、第三方认证、故障重试与可用性保障；
- 用户、账号、角色、统一认证与完整权限体系；
- 基于“普通管理员 / 超级管理员”等身份差异限制新增、删除、修改的逻辑；
- 评论、点赞、收藏、投稿、在线留言和工单；
- 站内全文搜索；
- 多级审核；
- 通用可视化 Page Builder；
- 复杂流量统计与用户画像；
- 多站点扩展；
- MQ、Redis、MinIO；
- 生产发布与正式环境拓扑。

## 4. CMS 建模原则

### 4.1 通用模型与工程资产边界

是否进入 CMS，以“是否存在持续运营维护价值”为核心判断，而不是机械消除硬编码。

优先进入 CMS 的数据包括：经常增删改的数据、数量或顺序会变化的数据、存在上下线周期的数据、需要由运营人员维护的站点属性。

优先保留为工程资产的内容包括：首页及页面稳定布局、固定 Shell、固定业务组件、基本不会变化的一次性外部平台集成、与程序实现强绑定且不需要运营维护的视觉资源或地址。

例如首页“国家大学生就业服务平台”区域属于固定工程集成；其 Logo、学生/企业入口和布局不要求提供后台管理。若未来发生真实产品需求变化，再按 Requirement Change 修改工程实现。

### 4.2 避免重复 Authority

同一业务数据只保留一个权威来源。不得同时通过网站属性 JSON、导航、前端常量维护同一组可运营数据。

复杂、可排序、可增删的业务集合不应长期存储为网站属性 JSON；JSON 仅保留为必要扩展类型，不代替正常 CMS 对象。

## 5. 内容模型

### 5.1 栏目与文章

栏目承担“栏目 → 内容列表 → 文章详情”的传统信息发布结构，至少支持名称、稳定 alias、父子层级、排序、启停。

栏目公开 URL：`/column/{alias}`。

文章至少支持标题、主栏目、富文本正文、来源、发布日期、封面/缩略图、附件、置顶、推荐、排序、草稿/已发布/已撤回、实际发布时间和浏览量。

文章区分“站内文章”和“外链文章”。外链文章只维护标题、发布日期、来源、原文链接及必要发布/排序属性，不复制外部正文、图片和附件；首页和栏目列表直接打开原文，新窗口为默认行为。站内文章 canonical URL 为 `/article/{id}`。

“招聘公告”栏目允许同时包含站内文章和外链文章；首页“招聘公告”区域只聚合已发布外链文章。

### 5.2 固定页面与页面组

固定页面具有稳定页面身份和公开 URL，不是“没有发布时间的文章”。普通固定页面为 `/page/{alias}`；页面组成员为 `/page/{groupAlias}/{alias}`。

页面组表达多个固定页面共享的业务组织和公共 Tab。Tab 必须由页面组成员数据生成，不在前端重复硬编码成员清单。

`guide` 页面组至少保持：`jypq`、`dagl`、`dygl`、`xlrz`、`contact`、`faq`；`jobs` 页面组保持在招职位、招聘简章、双选会、现场宣讲、留省就业占位。

## 6. 导航模型

### 6.1 导航位置

导航位置是独立 CMS 业务对象，而不是编译期 Enum。至少维护 code、名称、说明、排序、启停和系统标识。

站点初始化至少包含：

- `MAIN`：主导航；
- `HOME_SHORTCUT`：首页首屏右侧快捷入口；
- `HOME_QUICK`：首页快速导航。

后续可增加 Footer、移动端、专题导航等位置，而不要求修改后端枚举并重新发布程序。

### 6.2 导航条目

导航条目属于一个导航位置，支持父子层级、排序、启停、打开方式及目标类型。目标至少支持 HOME、COLUMN、PAGE、LINK、PLACEHOLDER。

父子导航必须处于同一位置；禁止形成循环；有下级菜单时不得直接删除父级。

主导航按现网结构初始化，包括网站首页、中心党建、招聘信息、业务指南、政策法规、就业指导、典型事迹、预决算公开、关于我们及其确认的二级菜单。“空中宣讲”不进入基线。

首页首屏右侧“就业信息填报、学历认证、全国征兵网、预决算公开、举报电话及邮箱”由 `HOME_SHORTCUT` 导航维护，不再通过网站属性 JSON 维护。

业务指南快捷入口由 `HOME_QUICK` 导航维护，避免前端同时维护一份页面清单。

## 7. 通用列表

CMS 提供通用列表与列表项，用于维护不属于导航、文章或广告的可排序展示数据。

列表至少维护 code、名称、分组、列表项类型、说明、排序、启停和系统标识；列表项至少支持标题、副标题、URL、图片、打开方式、排序、启停和必要扩展数据。

第一版列表项类型至少支持 `LINK`、`IMAGE_LINK`、`TEXT`。

首页轮播使用通用列表 `HOME_CAROUSEL`；网站导航区域中的友情链接/推荐网站组使用 `SITE_LINKS` 分组下的通用列表。不得继续使用 `HOME_BANNERS`、`SITE_LINK_GROUPS` 网站属性 JSON 作为运行时主数据源。

## 8. 广告位

CMS 提供广告位和广告内容模型。广告位代表公开站稳定布局中预留的推广区域；广告内容支持标题、图片、目标 URL、打开方式、启停、排序以及可选开始/结束时间。

首页“招聘活动横幅”使用广告位 `HOME_RECRUITMENT_PROMO`，不再作为单一网站属性图片路径维护。

轮播与广告位业务语义不同：轮播属于有序内容列表；广告位属于页面布局中的 Promotion Slot。两者可共享底层 UI/资源选择能力，但不强行合并为同一业务对象。

## 9. 网站属性

后台提供通用网站属性管理。网站属性至少维护 key、名称、分组、值、值类型、说明、排序、必填、系统标识和启停状态。

第一版值类型至少支持 `TEXT`、`RESOURCE_PATH`、`JSON`、`URL`、`BOOLEAN`。后端根据属性自身 `valueType` 验证值，不使用编译期枚举白名单限制可维护 key。

网站属性用于站点名称/简称、品牌资源、页头页脚公共信息、地址/电话/办公时间、备案/版权等真正的站点级属性。

`HOME_BANNERS`、`SERVICE_LINKS`、`SITE_LINK_GROUPS`、`HOME_PROMO_BANNER_PATH` 不再属于网站属性。`HOME_NCSS_LOGO_PATH` 取消 CMS 配置，NCSS 区域作为公开站工程资产固定集成。

当前阶段管理端可直接提供属性定义的新增、修改、删除以及属性值维护能力，不根据用户身份实施差异限制。

## 10. 静态资源与工程资产

网站提供独立静态资源管理，支持浏览目录/文件、上传、查看/下载、替换、删除到回收区、恢复及关键资源保护。

第一版不建设完整资源引用关系图。删除/替换必须提示系统不会扫描全部页面、CSS、JS、富文本或人工静态页面引用。

关键资源保护属于数据/运行安全措施，不等同于权限系统。当前阶段即使没有认证授权，也继续保留必要的路径验证、真实媒体类型验证、删除确认和关键资源保护。

站内特殊静态页面、固定 NCSS 集成、页面 Shell 等属于工程资产，不允许 CMS 用户上传任意 HTML/JavaScript 并执行。

## 11. 首页与公开站

首页采用固定模板，不建设通用 Page Builder。布局、尺寸关系、组件结构和主要视觉层级由公开站工程按现网复刻。

首页运营数据优先来自 CMS：普通资讯来自栏目/文章；主导航与快捷入口来自导航；轮播与友情链接来自通用列表；招聘活动横幅来自广告位；站点名称、联系方式等来自网站属性；固定 NCSS 集成等一次性设计保留为工程资产。

前台不得为了方便重新硬编码一份 CMS 已经提供的业务数据。若某数据明确属于稳定工程设计，则允许保留代码/静态资产实现。

首页第一版继续复刻：Header、主导航及二级菜单、轮播、通知公告、固定业务入口、招聘日历、就业动态、业务指南快捷入口、专题/宣传 Banner、招聘相关区域、招聘公告、NCSS 固定集成、网站导航/友情链接和 Footer。

## 12. URL、页面上下文与模板

公开 URL 与具体 HTML Entry 解耦。普通栏目 `/column/{alias}`，站内文章 `/article/{id}`，普通固定页面 `/page/{alias}`，页面组成员 `/page/{groupAlias}/{alias}`。

面包屑来自栏目/页面组/页面等业务关系，不从 URL 或某个导航入口机械推导。

普通栏目列表、文章详情、普通固定页和业务指南页面组继续以现网页面主要版式为复刻基准。

## 13. 初始化、测试与历史迁移

站点初始化基线由数据库基线数据 + 初始化静态资源包共同组成。Flyway 初始化后应具有栏目、导航位置与导航树、页面组、固定页面、必要网站属性、通用列表、广告位等真实站点骨架。

测试脚本只补充测试场景数据，不负责创建站点基础结构。历史文章与资源通过独立迁移机制处理，不混入 Flyway 基线。

## 14. 权限规划边界

后台最终复用智慧就业云平台统一账号和权限体系。未来可为栏目、导航、文章、页面、列表、广告、网站属性、静态资源分别提供权限点，并可规划“普通管理员主要维护值/内容，超级管理员维护高风险定义”的差异。

**上述内容当前只作为未来规划，不属于当前阶段实现或验收条件。** 当前阶段不得为此引入临时登录、角色、超级管理员标识或前端假权限。

## 15. 发布与公开规则

文章状态保持：`草稿 → 已发布 → 已撤回 → 已发布`。编辑不自动改变状态；只有已发布文章进入正常公开发现范围；撤回后从首页和栏目列表退出；不存在、已删除或已撤回内容直接访问显示统一不可用提示。

导航、列表项、广告、网站属性等公开数据只消费启用且满足自身有效条件的数据；广告若配置开始/结束时间，则公开端只返回当前有效广告。

## 16. 验收要点

当前迭代至少验证：

1. 现网主导航和二级结构按基线初始化并支持树形管理；
2. 导航位置独立维护，管理列表只展示当前选中位置的导航树；
3. `HOME_SHORTCUT` 驱动首页五个首屏快捷入口，前端不再读取 `SERVICE_LINKS` JSON；
4. `HOME_QUICK` 驱动业务指南快速入口，前端不重复硬编码成员列表；
5. 首页轮播由通用列表驱动；
6. 网站导航/友情链接由通用列表驱动；
7. 首页招聘活动横幅由广告位驱动；
8. 网站属性支持通用定义与类型化值校验，不依赖编译期 key Enum；
9. NCSS 首页区域使用固定工程集成，不提供 CMS 管理项；
10. 当前阶段不存在基于用户角色/权限的功能限制实现；
11. 栏目、文章、固定页面、页面组、公开 URL 和外链文章规则无回归；
12. 静态资源真实媒体验证、路径安全、关键资源保护和回收恢复无回归；
13. Flyway 干净初始化得到完整 CMS 站点骨架；
14. Backend、Public Site、Admin Frontend 与 Browser Verification 形成 Current Evidence；
15. Human Review Environment 能对新的 CMS 模型与管理体验进行重新评审。
