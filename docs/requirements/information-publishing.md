# 信息发布与网站服务需求

## 1. 文档目的

本文是 `jilinjobs-cms` 当前“信息发布与网站服务”业务需求基线，用于约束中心主站的网站结构、内容模型、前台页面、后台管理、初始化数据、历史迁移与当前迭代范围。

当前网站参照基线为“吉林省高等学校毕业生就业信息网”。`www.jilinjobs.cn` 因上级统一规划跳转到 `24365.jl.smartedu.cn`；在本项目的需求分析、页面结构分析、视觉取证和内容采集过程中，两者视为同一原网站。除这两个域名之外，页面引用或嵌入的其他域名原则上视为外部网站或外部系统。

本版本 V4.1 在 V4.0 视觉与结构基线基础上，补充 2026-08-28 人工确认的外链文章与页脚展示规则。与本文冲突的旧版“布局现代化”“本轮建设中心党建主题”“本轮完成第三方 iframe 实际集成”“不建设网站静态资源管理”等描述均被本版本替代。

## 2. 建设目标

当前迭代目标从“蓝—青色风格延续 + 布局现代化”调整为：

> **现网视觉与布局复刻 + 必要的技术性适配。**

具体目标：

1. 以原网站当前页面结构、主要布局关系、菜单/栏目结构和视觉识别作为新版主站基准；
2. 完整重建栏目、菜单、文章、固定页面、页面组、网站配置和网站静态资源等后台能力；
3. 首页、栏目页、文章详情页、固定页面和业务指南等典型页面优先复刻现网主要版式；
4. 使用新的 Vue / Spring Boot 技术实现，不复制旧网站前端代码；
5. 允许为响应式、浏览器兼容、明显易用性问题和工程实现进行必要调整，但不得以“现代化”为理由主动改变整体视觉识别、主要布局和信息结构；
6. 站点结构与确定内容形成可重复的初始化基线，测试数据与站点基线分离；
7. 原站历史运营内容通过独立迁移机制处理，不混入 Flyway 初始化数据。

## 5. 内容组织模型

### 5.1 菜单与栏目分离

菜单负责网站导航结构和入口展示；栏目负责组织普通信息发布内容。

菜单可以指向：首页、普通栏目、普通固定页面、页面组中的固定页面、特殊嵌入型固定页面、外部链接、占位入口。

存在菜单不意味着必须存在普通栏目。

本站业务对象优先通过对象关联形成菜单目标，由系统生成公开 URL；外部链接直接维护 URL。

打开方式默认规则：外部网站原则上新窗口打开；本站页面默认当前窗口打开；本站页面允许根据实际需要配置新窗口打开。

### 5.2 普通栏目与文章

普通栏目承担“栏目 → 内容列表 → 文章详情”的传统信息发布结构。

栏目至少支持名称、稳定 alias、父子层级、排序、启用/停用和栏目列表页。

栏目公开 URL：

```text
/column/{alias}
```

文章至少支持标题、主栏目、富文本正文、来源、发布日期、封面/缩略图、附件、置顶、推荐、排序、草稿/已发布/已撤回、实际发布时间和浏览量。

文章按内容承载方式区分为“站内文章”和“外链文章”。站内文章继续维护本站富文本正文、资源和附件，并使用本站文章详情页。外链文章用于聚合或抓取外部网站内容，本站只维护标题、发布日期、来源、原文链接及必要的发布/排序属性，不复制外部正文、图片和附件。

外链文章在首页和栏目列表中直接打开原文链接，按外部网站规则使用新窗口，不先进入本站文章详情页；即使用户直接访问其兼容文章地址，前端也应跳转原文链接。“招聘公告”栏目当前按外链文章组织，来源内容由外部网站采集或同步进入本站。

站内文章公开 URL：

```text
/article/{id}
```

站内文章 URL 不要求编码栏目层级。站内文章的栏目归属、页面层级和面包屑由业务数据关系决定，不依赖 URL 解析。同一站内文章无论从首页、栏目、推荐入口进入，使用同一个 canonical URL。外链文章以原文链接作为实际访问目标，本站 `/article/{id}` 仅作为兼容入口并重定向到原文链接，不作为其 canonical 内容地址。

### 5.3 固定页面

固定页面不是“没有发布时间的文章”，而是具有稳定页面身份和固定公开 URL 的内容对象。

普通固定页面 URL：

```text
/page/{alias}
```

页面组内固定页面 URL：

```text
/page/{groupAlias}/{alias}
```

固定页面至少具有后台管理名称、稳定 alias、所属页面组（可空）、正文、展示方式、排序和启用/停用。

固定页面前台默认不展示普通文章详情的来源、发布时间、浏览量等发布型元信息。页面内是否展示标题由页面内容和模板决定。

普通固定页面至少包括关于我们、预决算公开、就业创业师资库。

### 5.4 页面组

页面组表达多个固定页面共享的业务组织和前台公共导航，不等同于普通信息栏目。

页面组至少维护名称、alias、排序、启用/停用和成员页面顺序。公共 Tab 导航由页面组成员数据生成，不在前端硬编码。

### 5.5 业务指南页面组

业务指南采用专用页面组模型，共享全站 Header / Footer、页面位置/面包屑、业务指南公共 Tab、当前项高亮和主体内容区。

确认的固定 URL：

```text
/page/guide/jypq   就业派遣
/page/guide/dagl   档案管理
/page/guide/dygl   流动党员（alias 使用 dygl）
/page/guide/xlrz   学历认证
```

“联系我们”“常见问题”的 alias 在实现阶段按稳定、简洁规则确定。

业务指南第一版可以由通用 Page Shell 渲染；后续若公共导航或布局需要独立实现，可增加 Guide Shell，而不修改公开 URL。

“就业派遣”允许在固定页面内容区域内使用专用 Shell、组件或本站自行实现的静态页面，以支持普通富文本无法满足的特殊展示效果。

### 5.6 招聘信息页面组

招聘信息页面组成员为在招职位、招聘简章、双选会、现场宣讲、留省就业。

公开 URL 统一使用：

```text
/page/jobs/{alias}
```

本轮完成页面框架、公共 Tab、当前项和占位展示，不加载真实慧就业 iframe。

后续接入时，招聘信息可以由专用 Jobs Shell 承担嵌入尺寸、加载状态、移动端适配和第三方地址配置，但公开 URL 不变。

“就业指导 → 直播课程”属于同类外部嵌入呈现能力，但业务组织仍属于就业指导，不强制归入 jobs 页面组。

## 6. 多入口页面 Shell 与 URL 原则

公开 URL 与具体 HTML Entry 解耦。站点可以从单一 SPA 演进为多个 SPA Shell。URL 用于表达稳定页面身份；Nginx/前端构建入口用于选择渲染 Shell。

页面 Shell 采用“最具体实现优先、通用实现逐级回退”的设计原则：

```text
/page/guide/jypq
  → jypq 专用 Shell（如存在）
  → guide Shell（如存在）
  → page Shell
  → 默认 Shell
```

第一版不要求立即创建所有专用 Shell。只有当某类页面出现足够稳定的独立布局或运行机制时才增加专用 Entry。

公开 URL 只有一个 canonical 形式。即使 Nginx 技术上允许多个前缀映射同一 Shell，也不应让同一公开页面长期存在两套等价 canonical URL。

## 7. 面包屑与页面上下文原则

面包屑不从 URL 路径机械推导。面包屑属于页面上下文，由网站信息架构数据形成：栏目页来自栏目父子层级；文章详情来自文章主栏目及其祖先栏目；普通固定页面来自页面自身；页面组固定页面来自页面组 + 成员页面；招聘信息来自招聘信息页面组 + 当前成员；特殊静态实现仍以对应 CMS 页面身份形成上下文。

菜单是访问入口，不作为唯一面包屑来源。

## 8. 首页

### 8.1 固定模板

首页采用专门设计实现的固定模板，不建设通用 Page Builder。首页区域位置、尺寸关系、布局和主要视觉层级由前端代码按现网复刻；后台只维护必要的数据，不负责任意增加、删除、拖动区块或自定义组件。

### 8.2 数据来源

首页只组合和引用已有业务数据，不维护重复内容副本：普通资讯区来自栏目/文章；推荐/置顶来自文章展示属性；主导航来自菜单；Banner、Logo、固定图片来自网站配置 + 网站静态资源；固定业务入口来自网站配置；网站导航/友情链接来自结构化链接组；招聘、直播等外部内容本轮为占位。

文章被首页推荐不会改变栏目归属或发布状态；站内文章 canonical URL 保持不变，外链文章保持原文链接不变。

### 8.3 现网区域基线

首页第一版按原网站主要区域和相对顺序复刻，包括：顶部业务入口和 Header、网站标识、主导航及二级菜单、轮播/Banner、通知公告等重点资讯、固定业务/公共服务入口、招聘日历及招聘相关入口、就业资讯/就业动态、业务指南快捷入口、专题/宣传 Banner、最新招聘等外部内容区域、直播课程等外部内容入口、招聘公告、学生/用人单位等业务入口、网站导航/友情链接和页脚。

实现前和人工测试中允许根据现网页面证据校正精确区域名称、尺寸关系和数据条数，但不主动重构成与原站明显不同的门户布局。

## 9. 前台标准模板

### 9.1 普通栏目列表页

以现网标准栏目列表页为复刻基准：全站 Header / 主导航、页面位置/面包屑、栏目名称、已发布文章标题 + 日期、分页和 Footer。

### 9.2 普通文章详情页

以现网详情页为复刻基准：Header / 主导航、页面位置/面包屑、标题、来源、发布时间、正文、图片、附件、链接复制/二维码等基础分享和 Footer。

### 9.3 普通固定页面

普通固定页面采用统一页面框架：Header / 主导航、页面位置/面包屑、固定内容区域和 Footer，不强制套用普通文章元信息。

## 10. 网站配置管理

后台提供“网站配置管理”，用于维护系统预先定义的站点级公共配置，而不是任意 Key-Value 配置中心。

配置范围可包括网站名称/简称、Logo、页头/页脚信息、地址/电话/办公时间、备案/版权、首页固定 Banner、固定业务入口、网站导航/友情链接等结构化链接组以及其他明确的站点级展示配置。

主导航仍由菜单管理负责；栏目、文章、固定页面正文不进入网站配置。

## 11. 网站静态资源管理

网站提供独立的高权限静态资源管理能力，用于方便管理站点公共静态资源，包括后台上传资源和直接放入指定静态目录的既有文件。

第一版至少支持浏览目录和文件、上传、下载/查看、替换、删除、回收/恢复和必要的关键资源保护。

第一版不建设通用资源引用关系管理，也不承诺判断某个静态资源是否正在被所有页面、CSS、JS、富文本或人工静态页面引用。

删除/替换必须明确提示“系统不会完整检查该资源是否正在被页面引用”。

普通内容资源仍使用自身内容—资源关联机制；网站静态资源管理不取代文章附件和正文图片管理。

静态资源管理属于高风险能力，普通内容编辑人员默认无权使用；后续统一权限体系应提供独立权限点。当前原型阶段不为此单独建设临时认证系统，但保留明确权限边界。

后台不得提供任意上传并执行 HTML/JavaScript 的能力。

## 12. 站内静态页面

站内静态页面属于工程实现资产，不是 CMS 用户自由创建的内容类型。其用途是为普通富文本无法满足的固定页面提供更强的布局和交互表现。

规则：由开发过程设计、编码、测试并随前端应用部署；可以由固定页面配置引用；可以使用站点静态资源；是否采用 iframe、专用 Shell 或组件加载由技术设计决定；公开 URL 仍以 CMS 固定页面身份为准；后台不允许上传任意 HTML/JS 并直接执行。

## 13. 后台能力边界

当前后台职责划分为栏目管理、菜单管理、文章管理、固定页面管理、网站静态资源管理和网站配置管理。

前台可以根据展示机制拆分多个 Shell；后台不因此按每个 Shell 创建独立业务管理模块。

## 14. 初始化基线

站点初始化基线由“数据库基线数据 + 初始化静态资源包”共同组成。

数据库基线至少包含确认后的栏目树、主菜单和二级菜单、页面组、固定页面及 alias、菜单目标关系、必要的网站配置、少量属于站点结构本身的固定页面初始正文，以及初始化静态资源的稳定路径/元数据引用。

初始化静态资源包至少可包含 Logo、固定 Banner、固定图标、已确认需要随站点提供的人物头像和其他属于初始站点状态的资源。

原则：使用新增 Flyway migration 固化结构化数据库基线，不回改已执行历史 migration；初始化对象使用稳定 code/alias，不依赖自增 ID 作为长期业务标识；二进制文件不直接写入 SQL；测试脚本不负责创建站点基础结构；初始化数据部署后仍可由后台正常维护。

## 15. 测试数据

测试数据与站点初始化基线严格分离。测试用例可按需创建草稿/已发布/撤回文章、测试附件、置顶/推荐和边界失败场景。

Review Environment 启动时，执行 Flyway 后应已经具有真实菜单、栏目、页面组、固定页面和站点配置；Playwright 仅补充验证场景数据。

## 16. 历史内容迁移

历史内容迁移与初始化基线分离。历史迁移范围包括历史文章、正文图片、封面、附件、来源和发布日期、原栏目归属、可识别旧 URL 映射。

完整历史文章不通过 Flyway 固化。上线前使用专项迁移程序、数据包或一次性脚本完成。开发和普通自动化测试环境不要求每次加载全部历史内容。

## 17. 历史 URL 兼容

新版使用新的规范 canonical URL。对能够可靠识别和映射的原站历史 URL，通过兼容层重定向到新版 URL，不要求继续沿用旧站 URL 结构。无法可靠识别的旧地址不通过猜测强行兼容。第三方外部地址不属于本站历史 URL 兼容责任。

## 18. 视觉与交互

新版以前述原网站为视觉与信息架构基准，重点保持 Header、Logo、导航、Footer 的整体形式；首页主要内容区域的布局和位置关系；蓝—青色主视觉；栏目标题、列表、详情、固定页的主要版式；能够取得并确认的原站 Logo、Banner、图标等视觉素材。

不要求像素级复制，也不复制旧代码。允许必要的响应式、浏览器兼容和明显易用性调整，但不能主动改变整体识别和主要布局。

重点支持 Chrome、Edge、Android 主流浏览器、微信内置浏览器、iPhone Safari；Firefox 作为一般兼容目标。不要求 Internet Explorer。

## 19. 权限边界

后台最终复用智慧就业云平台统一账号和权限体系。至少需要预留栏目管理、菜单管理、文章编辑/发布、固定页面管理、网站配置管理、网站静态资源管理权限。

网站配置和静态资源属于高风险能力，要求更高权限。当前独立原型不建设认证授权，只用于验证业务行为；此阶段性简化不能解释为正式系统所有后台用户均有高风险权限。

## 20. 发布与公开规则

文章状态：

```text
草稿 → 已发布 → 已撤回 → 已发布
```

规则：新文章默认草稿；编辑不自动改变状态；只有已发布文章进入正常公开发现范围；撤回后从首页和栏目列表退出；不存在、已删除或已撤回内容直接访问显示统一不可用提示；首页推荐、置顶、排序不改变文章发布状态。站内文章公开后进入本站详情页；外链文章公开后首页和栏目列表直接指向原文链接，不复制外部正文。
