# 管理端操作提示与解释责任治理需求

## 1. 背景与目的

当前 CMS 管理端已经形成文章、单页、列表、栏目、导航、宣传展示、网站属性和静态资源八类正式管理入口。随着前期模型、预置保护、图片策略、页面呈现方式和模块边界不断收敛，一部分实现阶段说明被直接保留在运营界面中，导致同一页面同时承担：

- 当前操作所需的校验、状态和风险提示；
- 稳定结构身份说明；
- 公开站设计理由；
- Backend / Database / 部署实现说明；
- Requirement / Method 背景解释。

管理端应优先帮助运营人员完成当前任务，而不是要求其理解实现背景。本文在不改变现有 CMS 数据模型、API 和业务规则的前提下，对用户可见提示、字段命名和解释责任进行收敛。

本文对 `docs/requirements/information-publishing.md` 的 CMS 管理体验形成定向补充；未明确修改的既有需求继续有效。

## 2. 核心原则

### 2.1 必须保留的操作信息

以下信息属于当前操作所必需内容，必须继续在 UI 中清晰表达：

- 保存前校验失败及必填条件；
- 发布、撤回、启停等状态后果；
- 删除、替换等不可逆或可能影响公开访问的操作确认；
- 当前控件状态无法自然表达的关键限制，例如创建后不可修改的身份属性；
- 静态资源受保护状态及引用风险；
- 外链文章、`NO_LINK` 等会直接改变当前用户预期的行为语义。

### 2.2 不应由运营 UI 承担的信息

以下内容不应作为长期运营提示持续展示：

- “字段不决定公开页面布局/尺寸”等设计职责解释；
- “随前端工程部署”“由 Backend / Database / 部署配置负责”等实现说明；
- “当前 Requirement 不……”之类 Method / Authority 解释；
- 仅为开发者说明数据来源、metadata 存储位置或模块装配方式的内容；
- 已经由字段显隐、标签、只读值或合理默认值自然表达的重复 Alert。

这些内容如仍有维护价值，应由 Requirement / Specification / Technical Plan / 代码维护说明承载，而不是复制到运营页面。

### 2.3 结构身份字段的产品表达

`alias / code / key` 等字段在当前模型中仍承担真实稳定身份，不因本轮 UX 治理而删除或修改 Backend contract。

面向运营人员时，应优先使用能表达用途的中文标签：

- 栏目、单页、单页分组 `alias`：**公开标识**；
- 列表 `code`：**列表标识**；
- 导航位置 `code`：**位置标识**；
- 展示位 `code`：**展示位标识**；
- 网站属性 `key`：**属性标识**。

在确实需要创建这些对象时仍允许录入稳定标识；编辑预置结构或其他不可变身份时，使用自然的只读/disabled 表达和简短限制说明，不要求用户理解“稳定站点身份”等实现语言。

## 3. 本轮治理范围

### 3.1 文章管理

- 栏目 `coverPolicy=NONE` 时，封面编辑字段已经隐藏，不再额外显示“当前栏目不使用文章封面图片”提示；
- `REQUIRED` 时继续提示“草稿可暂存，发布前必须设置封面”；
- 文章类型创建后不可修改的提示保留，但收敛为当前操作限制；
- 排序说明只表达实际排序规则，不在表单中解释“列表投放”等架构职责；
- 外链文章跳转语义和保存不改变发布状态的提示继续保留。

### 3.2 栏目与列表

- 栏目 Alias 使用“公开标识”表达；列表 Code 使用“列表标识”表达；
- 保留栏目封面要求、列表图片要求的真实数据约束；
- 删除“这些策略不决定公开页面布局/图片位置”等设计职责说明。

### 3.3 单页

- 单页和单页分组 Alias 使用“公开标识”；
- `INTERNAL_STATIC / EMBED_PLACEHOLDER` 只说明当前可操作行为，不在弹窗中解释前端工程部署、任意 HTML/JS、当前 Requirement 等实现背景；
- 删除单页可能导致公开地址不可用的风险确认继续保留。

### 3.4 导航与宣传展示

- 导航位置 Code 使用“位置标识”；展示位 Code 使用“展示位标识”；
- 导航条目编辑时，当前位置是已有管理上下文，不使用 disabled 技术输入重复表达；应改为自然只读上下文；
- `NO_LINK` 下 URL 保留的操作语义继续保留，但使用简洁用户语言。

### 3.5 网站属性

- Key 使用“属性标识”；
- 删除页面顶部关于 Database / 上传安全配置职责的工程说明；
- 删除“分组来自资源 metadata / 部署配置、不在数据库维护”等实现来源说明；
- 保留属性定义与属性值分离的操作入口，并用简短用户语言提示从“编辑值”修改当前值；
- 属性自身 `description` 若是该属性的真实运营说明，继续在值编辑弹窗中展示。

### 3.6 静态资源

静态资源属于高风险管理能力。本轮不得以“减少提示”为由弱化安全信息：

- 受保护状态继续展示；
- 删除和替换确认继续说明可能影响公开页面；
- 系统无法检查全部引用的限制继续表达，但改为用户可理解的操作风险，不强调 CSS / JS / Backend 等实现名词。

## 4. 非目标

本轮不修改：

- CMS 数据库 Schema；
- Backend API、DTO 或持久化字段；
- preset 保护语义；
- 用户权限模型；
- Public Site 页面行为或视觉；
- Article / Page / List / Navigation / Advertisement / SiteProperty 的业务模型；
- 富文本编辑能力升级（Issue #60 / B3）；
- Loading / Skeleton、Mobile Review 等其他候选。

## 5. 验收要求

1. 八类 Admin CMS 页面不再把 Requirement、数据库、部署、前端工程或公开页面设计职责作为长期运营说明展示；
2. 稳定身份字段仍可按现有 contract 创建/保存，但用户可见标签改为业务可理解的“公开标识 / 列表标识 / 位置标识 / 展示位标识 / 属性标识”；
3. 栏目不使用封面时，文章表单不显示封面字段，也不显示额外“无封面” Alert；
4. REQUIRED 封面、外链文章、文章状态、`NO_LINK` 等真实操作语义仍可见；
5. 单页特殊呈现模式不再出现“前端工程部署 / 当前 Requirement / 任意 HTML/JS”等实现说明；
6. 网站属性页面不再展示 metadata / Database / 部署来源解释，但属性 description 和值编辑分离仍正常；
7. 静态资源删除/替换/保护风险不得因本轮清理而消失；
8. 现有 Admin 功能、Backend contract、Public 行为和既有回归测试无业务回归；
9. 新增 Browser Evidence 直接验证“冗余/实现说明消失 + 必要操作风险仍存在 + 关键表单可继续使用”。
