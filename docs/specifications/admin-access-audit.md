# CMS 管理访问与操作审计规格

## 范围

本规格描述第一版管理访问、身份反馈、隔离测试登录和可观察审计结果。当前 Backend 已实现 Admin 请求 / 方法授权、Public 匿名回归边界、管理写操作审计产生和持久化以及 `super` 专属审计查询，Admin 已提供对应只读页面；全局管理页面身份反馈与隔离测试登录正在进入独立实施，正式身份提供方仍待目标宿主协议明确后接入。既有 CMS 编辑、发布和资源行为继续由 `admin-site.md` 持有，本规格只增加访问与审计边界。

## 管理访问

- 未认证访问管理页面或 `/api/admin/**` 时不能读取、创建或修改管理数据；界面进入可理解的待登录 / 无法认证状态，API 返回明确的未认证结果。
- 认证有效但没有 `admin` / `super` 角色时拒绝管理操作；已认证但无对应权限时返回明确的禁止访问结果，不能显示成功状态或使用公开 API 替代管理接口。
- `admin` 可完成既有 CMS 业务管理操作，但不能查询审计记录；`super` 可完成上述操作并查询审计记录。两者均受既有业务验证和受保护对象约束。
- 公开站及 `/api/public/**`、公开资源的现有读取行为不因管理端认证而被要求登录；不得让公开 API 暴露管理数据。
- 凭证失效后后续管理请求必须拒绝。直接访问、刷新和同一管理流程的 API 调用保持一致的身份状态。
- 测试模拟身份仅用于隔离开发、自动化测试和人工评审；正式部署不能通过该入口获得管理权限。

## 管理端身份反馈与隔离测试登录

- 管理端首次进入时先确认当前管理身份；确认期间显示明确的检查状态，不在身份未知时提前加载管理数据。
- 未认证或身份失效时，管理工作区不展示为可用状态，并保留用户原本访问的管理位置。真实身份环境提示通过所属平台完成认证并允许重试；隔离 Review 环境同时展示明确标注为“仅测试”的模拟登录入口。
- Review 模拟登录允许测试人员选择 Server 预置的 `admin` 或 `super` 测试主体。选择项不能携带任意用户 ID、身份来源或角色声明；成功后显示实际返回的 `identitySource`、`userId` 和 CMS 角色。
- 已认证管理端统一显示当前主体与角色。Review 会话允许主动退出和模拟身份失效；完成后下一次及后续 Admin 请求均返回未认证状态，页面回到身份入口且不得继续显示已认证成功状态。
- `admin` 不展示只有 `super` 才能使用的审计导航；直接访问审计地址或页面内请求仍由 Backend 返回 `403`，页面显示禁止访问而不是空数据、成功或重定向到公开 API。
- 任一管理页面或管理 API 在使用过程中返回 `401` 时，全局身份状态转为未认证 / 已失效；`403` 保留有效主体并形成可理解的禁止访问反馈。各业务页面不得通过各自不一致的通用异常掩盖这两类状态。
- Review 登录会话不构成 CMS 用户账号、密码登录或正式 SSO；关闭 Review 会话、刷新正式构建或访问正式 Server 时，不能凭 Review 状态获得管理权限。

## 操作审计

- 成功提交的管理写操作可按业务对象、动作、时间和操作者标识追溯；记录保留操作时的角色和结果，不依赖用户详情查询。
- 业务执行失败或事务回滚不显示为成功操作；拒绝访问不伪装为已执行业务写操作。
- 普通管理接口不能修改或删除审计记录；`super` 可以按有界条件分页查询，不允许无界全量读取。第一版不要求导出或用户详情展示。
- 审计中不显示密码、令牌、完整富文本正文等敏感或无关数据。

## 审计查询

- `super` 可从管理端“操作审计”入口查看按开始时间倒序排列的审计事件；相同时间的记录保持确定顺序，新记录进入后不应导致继续翻页时重复或遗漏既有记录。
- 每条记录展示审计 ID、请求关联标识、身份来源、用户 ID、操作时角色快照、动作、对象类型、可用对象标识、开始 / 完成时间与结果。`STARTED` 明确表示“结果未确认”，不能显示为成功。
- 查询可按完整操作者标识（`identitySource + userId`）、动作、对象类型 / 对象标识、结果、开始时间范围和请求关联标识进行精确过滤；改变过滤条件后从结果第一页重新开始。
- 列表必须使用有界分页，允许继续查看下一页和返回本次浏览中的上一页；不为了显示总数执行无界统计。没有下一页时明确结束，不用固定上限静默截断全部历史。
- 记录详情只展示该审计事件已经持久化的字段和角色快照，不反向读取已变化或已删除的业务对象，不补充用户详情，也不显示请求正文、文件内容、Rich Text 正文、异常消息或堆栈。
- `admin`、无允许角色和未认证主体不能读取任何审计列表或详情；页面必须呈现可理解的未认证 / 禁止访问 / 加载失败状态，不能用空列表掩盖权限或服务错误。
- 第一版查询为只读，不提供修改、删除、导出、保留期限设置、长期 `STARTED` 自动处置或外部审计平台操作；读取审计记录本身不产生新的业务写操作审计。

## 验收

以两个不同身份来源、`admin`、`super`、无允许角色、无效凭证分别验证相同用户 ID 的隔离、授权结果与审计操作者标识；覆盖现有每类 Admin API 的代表性读写操作及资源上传 / 删除、文章发布 / 撤回。验证提交成功、业务失败、回滚、直接刷新、正式配置拒绝测试身份，并回归 Public 行为。

管理端身份闭环还须验证：首次检查期间不加载管理数据；匿名直接访问与刷新进入身份状态；Review 测试人员可以分别以 `admin`、`super` 登录并看到 Server 返回的真实主体；`admin` 菜单裁剪与审计直达 `403` 同时成立；退出及模拟失效后当前和后续请求均为未认证；页面内任意 Admin 请求的 `401 / 403` 进入一致反馈；正式 Frontend / Server 组合不能激活 Review 登录；Public 页面和 API 不受影响。

审计查询还须验证：只有 `super` 可读取；分页边界稳定且单页大小受限；操作者、动作、对象、结果、时间与请求关联过滤可组合；详情保持历史角色与对象标识；`STARTED`、`FAILED`、`ROLLED_BACK` 不被误呈现为成功；响应和页面不包含被排除的敏感数据；查询行为不产生新的业务审计记录。

具体测试层次、目标提交和运行时证据遵循 `docs/technical/verification-strategy.md`。
