# 中心主站信息发布核心能力规格说明（Specification）

## 1. 目标

当前迭代为中心主站建立最小但完整的信息发布闭环：后台能够维护栏目、导航和本站文章，并通过明确的发布状态控制公开可见性；公众无需登录即可通过主站首页、栏目/二级页面和内容详情页面查找、浏览与直接访问已发布内容。

本规格说明只描述当前迭代的 WHAT / WHY，不规定技术栈、数据库、接口形式、源码目录或具体实现步骤。

## 2. 权威与适用边界

本规格依据以下 Consumer Authority 形成：

1. `AGENTS.md`；
2. `README.md`；
3. `docs/requirements/information-publishing.md` 中落入当前迭代 Scope 的详细业务要求。

`docs/requirements/information-publishing.md` 中指向当前 Consumer Repository 不存在文件的 upstream references 不构成本规格的事实来源。

当前 Authority 对后台业务对象明确了栏目层级，并允许网站导航按类别组织；本规格不据此发明独立的标签/分类内容模型。后续若需要独立标签或分类体系，应由新的 Consumer Authority 明确后再增量更新 Specification。

## 3. 当前范围（Scope）

### 3.1 In Scope

本轮包括：

- 中心主站栏目结构维护；
- 与栏目及公开访问相关的菜单、主导航、服务入口和网站导航组织；
- 本站文章的创建、编辑、发布、撤回和重新发布；
- 文章正文图片、封面和附件等随内容维护的资源；
- 中心主站首页；
- 栏目/二级页面；
- 内容详情页面；
- 已发布内容的公开直接访问、链接复制和基础分享支持；
- 文章浏览量的简单记录与后台查看；
- 当前公开页面所需的响应式、浏览器兼容和基础搜索引擎友好要求。

### 3.2 Out of Scope

本轮不包括：

- 第三方内容 iframe 嵌入及其降级展示；
- 用户、账号、角色、权限体系以及后台认证授权机制的建设或集成；
- “中心党建”独立主题、栏目首页及其专属内容组织；
- 评论、点赞、收藏、投稿、留言、咨询等互动能力；
- 站内全文搜索；
- 独立公共素材库；
- 多级内容审核流程；
- 复杂流量分析、用户画像、来源分析和统计报表；
- 多站点能力；
- 通用可视化页面设计器；
- 历史内容迁移及旧地址兼容；
- 高保真原型交付；
- 外部业务系统内部的认证、查询、办理或业务处理。

当前系统是用于验证网站信息发布核心能力的可运行原型应用。当前原型后台不设置登录、身份认证或权限授权门槛，直接用于验证栏目、导航、文章维护和发布等业务行为。该简化只适用于当前原型阶段，不代表未来正式系统的安全边界。

外部网站或业务系统的链接可以作为导航目标存在，但本系统只负责导航，不负责外部系统本身的业务能力。

## 4. 必需行为（Required Behaviors）

### 4.1 栏目结构维护

后台应能够维护中心主站的栏目层级，使公开内容具有稳定、可理解的归属关系。

需要支持：

- 新增栏目；
- 修改栏目名称及展示相关信息；
- 调整栏目排序；
- 启用或停用栏目；
- 维护一级栏目及其子栏目；
- 配置栏目在主站导航中的组织关系和展示顺序；
- 为栏目确定当前主站页面所需的内容承载方式。

已有下属栏目或内容的栏目不得被直接删除，必须先处理其下属关系和内容归属，避免产生失去归属的公开内容。

### 4.2 菜单与导航组织

后台应能够维护中心主站公开访问所需的导航条目，包括主导航、服务入口和分类网站导航等当前主站范围内的入口。

每个导航或链接条目至少应具有能够表达其公开展示与跳转结果的信息，包括：

- 名称；
- 目标地址或目标栏目；
- 展示位置或所属导航类别；
- 排序；
- 启停状态。

启用的导航条目按配置参与公开页面展示；停用条目不应继续作为正常公开入口展示。

导航至本站内容时应进入对应栏目或内容页面；导航至外部网站或业务系统时，本系统只负责正确跳转，不承担目标系统的认证、可用性和业务处理责任。

### 4.3 本站文章维护

后台应支持创建和维护本站文章。文章业务信息至少包括：

- 标题；
- 所属栏目；
- 富文本正文；
- 内容来源；
- 发布日期；
- 封面图片或列表缩略图；
- 一个或多个附件；
- 是否置顶；
- 是否推荐；
- 展示顺序；
- 内容状态；
- 实际发布时间；
- 最后修改时间；
- 浏览量。

发布日期允许后台维护，以支持内容补录等业务场景；公开页面主要展示发布日期。

正文应允许使用内容所需图片；附件应随文章维护，不要求建设独立素材库。

### 4.4 发布状态与公开可见性

新建文章首先形成草稿。

当前发布状态只有：

```text
草稿 → 已发布 → 已撤回 → 已发布
```

当前原型后台使用者可以直接发布、撤回和重新发布内容；本轮不建设多级审核流程，也不通过认证授权机制限制这些原型操作。

发布状态必须决定文章是否进入公众正常可访问范围：

- 草稿：不作为公开内容展示；
- 已发布：可以进入首页、栏目列表和独立详情地址的公开展示；
- 已撤回：退出正常公开展示，直接访问时显示统一的不可用提示。

修改已有文章只更新内容本身，不应自动改变其当前发布状态。

### 4.5 主站首页

中心主站首页应成为当前迭代公开内容的主要发现入口之一。

首页至少应能够：

- 展示中心主站的主导航及必要的子栏目入口；
- 按栏目组织并展示已发布内容的摘要或列表；
- 支持以栏目最新已发布内容为默认内容来源；
- 对已确认需要突出展示的文章体现推荐、置顶或展示顺序；
- 展示当前配置中启用的服务入口或网站导航；
- 提供进入对应栏目/二级页面和内容详情页面的明确入口。

首页只消费已发布内容，不因为首页推荐、置顶或排序操作而改变来源文章的发布状态。

本轮首页不要求展示“中心党建”专属主题区，也不要求承载第三方 iframe 内容。

### 4.6 栏目/二级页面

栏目/二级页面应让公众理解当前位置并浏览该栏目中的公开内容。

当前至少需要：

- 展示栏目名称；
- 提供能够表达栏目层级关系的导航信息；
- 展示该栏目下已发布文章的标题和发布日期；
- 当内容数量超过单页承载范围时支持分页浏览；
- 允许进入对应内容详情页面；
- 不展示草稿或已撤回文章作为正常公开列表项。

### 4.7 内容详情页面

每篇已发布文章应具有可直接访问的独立地址。

内容详情页面至少展示：

- 标题；
- 内容来源；
- 发布日期；
- 正文；
- 正文图片；
- 附件及附件下载入口；
- 当前页面链接复制入口；
- 当前页面访问二维码。

公开详情地址应支持浏览器正常刷新、前进和后退，复制后的地址能够再次直接打开对应内容。

已撤回、已删除或不存在的内容直接访问时应显示统一的不可用/不存在提示，而不是继续呈现为正常公开内容。

本轮不直接集成微信、微博等第三方分享接口。

### 4.8 浏览量

系统应记录文章的简单浏览次数，并允许后台查看文章访问次数。

该能力只用于单篇文章的基础访问记录，不扩展为独立流量分析、用户画像、来源分析或复杂统计报表。

## 5. 业务规则（Business Rules）

1. **公开内容只来自已发布状态。** 首页、栏目列表及其他正常公开发现入口不得把草稿或已撤回文章当作公开内容展示。
2. **发布状态与内容编辑解耦。** 编辑文章不自动发布，也不自动撤回已经发布的文章。
3. **栏目归属必须保持有效。** 不允许通过直接删除仍承载下属栏目或内容的栏目制造无归属内容。
4. **首页组织不改变内容所有权或发布状态。** 推荐、置顶、排序只是展示组织行为。
5. **本站查找边界明确。** 用户通过首页、栏目导航和内容列表查找本站内容；本轮不提供站内全文搜索。
6. **外部入口只负责导航。** 目标系统中的身份认证、查询和业务办理不属于本系统。
7. **当前原型不处理认证授权。** 本轮既不建设账号、角色和权限体系，也不接入外部认证授权机制；后台直接用于验证信息发布核心业务。正式系统的身份与权限边界留待后续项目阶段重新建立 Authority。

## 6. 边界与失败行为（Boundary / Failure Behavior）

- 访问已撤回、已删除或不存在的文章时，显示统一提示，不展示为正常详情页。
- 导航条目被停用后，不继续作为正常公开入口展示。
- 栏目存在下属栏目或内容时，直接删除应被拒绝或阻止，直到依赖关系被处理。
- 外部导航目标不可用时，不要求本系统自动探测、缓存、同步或重试目标站点。
- 当前迭代不因外部业务系统失败而扩展本站业务处理职责。

## 7. 相关非功能约束（Relevant Non-functional Constraints）

### 7.1 公开访问

中心主站公开内容面向互联网用户，无需注册或登录即可访问。

### 7.2 响应式适配

首页、栏目/二级页面和内容详情页面应可在桌面、平板和手机浏览器中正常使用；移动端应支持导航折叠、内容列表重排和图片自适应，不依赖只适用于桌面的固定宽度布局。

### 7.3 浏览器兼容

当前公开页面重点支持：

- Chrome；
- Edge；
- Android 主流浏览器；
- 微信内置浏览器；
- iPhone Safari；
- Firefox 作为一般兼容目标。

不要求 Internet Explorer 兼容。

### 7.4 主站视觉边界

中心主站延续蓝—青色主题和现有信息分区识别特征，同时允许在不改变已确认栏目与业务入口边界的前提下优化布局、层级、字体、留白和交互表现。

### 7.5 基础搜索引擎友好

已发布文章应具备清晰、稳定、可直接访问的内容地址，并具有合理的页面标题和摘要，使公开内容具备基础搜索引擎收录条件。

本轮不建设复杂 SEO 运营、关键词管理或收录效果分析。

## 8. 验收标准（Acceptance Criteria）

当前迭代达到 Specification 层面的完成标准，需要能够以可观察行为证明以下结果：

1. 后台可以新增、修改、排序、启停中心主站栏目，并维护一级栏目与子栏目关系。
2. 对仍有下属栏目或内容的栏目，系统不会允许直接删除并留下无归属内容。
3. 后台可以维护主导航、服务入口和网站导航等当前主站入口，并控制名称、目标、位置/类别、排序和启停状态。
4. 后台可以创建本站文章，并维护标题、栏目、正文、来源、发布日期、图片、附件及展示相关信息。
5. 新文章默认为草稿；文章可以按“草稿 → 已发布 → 已撤回 → 已发布”流转。
6. 编辑文章不会自动改变其发布状态。
7. 只有已发布文章进入首页、栏目列表和正常详情访问范围；草稿不会公开展示，已撤回内容直接访问时显示统一提示。
8. 主站首页能够通过主导航、栏目内容和配置的入口把公众引导至当前范围内的栏目/二级页面和详情页面。
9. 栏目/二级页面能够展示栏目位置、已发布文章标题与发布日期，并在需要时分页。
10. 已发布文章具有可直接访问的独立详情地址，页面能够展示标题、来源、发布日期、正文、图片和附件。
11. 详情地址复制后可以直接再次访问对应已发布内容，并提供链接复制和二维码入口。
12. 已删除或不存在内容直接访问时显示统一提示。
13. 文章浏览量可以记录并在后台查看，但没有独立复杂统计分析能力。
14. 公开页面无需登录即可访问，且桌面、平板和手机端主要页面均能正常使用。
15. 当前主站不出现“中心党建”专属主题实现、第三方 iframe 嵌入、互动功能、全文搜索、多站点、用户权限体系或认证授权接入等越界能力。
16. 已发布内容具备稳定直接地址和基础搜索引擎友好信息，但不存在复杂 SEO 运营能力。
17. 当前原型后台无需登录、认证或授权即可进入并验证栏目、导航、文章维护与发布行为。

## 9. Fresh Agent 规格就绪检查

一个不依赖当前 Conversation History 的 Fresh Agent，在读取 `AGENTS.md`、`README.md`、本 Specification 以及必要的详细需求章节后，应能够明确判断：

- **What**：当前要交付中心主站的栏目、导航、本站文章发布闭环和三级公开页面；
- **Not What**：当前不建设党建主题、第三方嵌入、用户权限与认证授权、互动、全文搜索、复杂统计、多站点、历史迁移等相邻能力；
- **Completion**：第 8 节的可观察结果全部满足；
- **Ambiguity**：当前没有需要通过猜测才能决定的 Product Goal、Scope 或 Acceptance；技术栈与系统结构由 Technical Planning 持久化，不在本 Specification 中重复定义。
