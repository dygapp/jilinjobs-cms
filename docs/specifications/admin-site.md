# CMS 管理端规格说明（Specification）

## 1. 目标

本文定义独立 CMS 管理端的 WHAT / WHY。共享业务模型以 `docs/specifications/cms-core.md` 为准；公开站展示规则以 `docs/specifications/public-site.md` 为准。

管理端目标是提供通用、可复用的 CMS 管理体验，而不是把当前首页每个视觉区块都做成专用配置页面。

## 2. 管理信息架构

当前管理端至少提供：

- 文章管理；
- 栏目管理；
- 导航管理；
- 固定页面 / 页面组；
- 列表管理；
- 广告管理；
- 网站属性；
- 静态资源。

管理端保持独立 `/admin/` SPA 和统一 Application Shell。

## 3. 导航管理

导航页面必须先选择导航位置，再管理该位置下的树形导航条目。主数据表只显示当前位置的数据，不再把 `position=MAIN` 作为每行重复字段展示。

推荐交互为左侧导航位置列表 + 右侧树形 Table；位置数量很少时允许 Tab，但数据模型不得依赖 Tab 常量。

导航位置允许当前阶段直接新增、修改、删除；导航条目支持树形新增/编辑/删除、目标对象、打开方式、排序、启停。父级候选只显示当前导航位置内条目。

## 4. 通用列表管理

列表管理允许维护列表定义及列表项。列表项表单根据 `itemType` 显示相应字段：

- LINK：标题 + URL；
- IMAGE_LINK：标题 + 图片 + URL；
- TEXT：标题/副标题等文本。

当前首页轮播和网站导航/友情链接通过此通用入口维护，不建立首页专用“轮播配置 JSON”。

## 5. 广告管理

广告管理允许维护广告位和广告内容。广告内容至少支持图片、链接、打开方式、排序、启停和可选有效时间。

首页招聘活动横幅通过 `HOME_RECRUITMENT_PROMO` 广告位维护。

## 6. 网站属性

“网站配置”收敛为“网站属性”。管理端显示属性名称、key、分组、类型和值，并允许新增、编辑、删除属性定义。

类型化编辑和校验至少覆盖 TEXT、RESOURCE_PATH、JSON、URL、BOOLEAN。JSON 保存前执行真实解析；RESOURCE_PATH 使用 `/static/**`；URL 使用站内路径或 HTTP(S) 规则。

当前阶段不根据用户身份隐藏新增/删除按钮，也不实现普通管理员/超级管理员差异。相关限制只作为未来权限规划。

## 7. 风险操作

删除、关键资源替换等继续提供确认和业务保护。此类保护属于运行安全，不依赖认证授权。

静态资源继续提示“不提供完整引用检查”。不得开放任意 HTML/JavaScript 上传执行能力。

## 8. Acceptance Criteria

- 管理端导航入口扩展到列表、广告、网站属性；
- 导航管理按位置 + 树形结构呈现；
- 导航位置能够作为数据维护，而非编译期固定选项；
- 通用列表可维护首页轮播和友情链接数据；
- 广告管理可维护首页招聘活动横幅；
- 网站属性可维护定义和值并进行类型校验；
- 当前阶段无登录/角色/权限实现；
- 既有文章、栏目、页面、静态资源管理能力无回归；
- Browser E2E 覆盖至少导航位置、列表、广告、网站属性各一条核心路径。
