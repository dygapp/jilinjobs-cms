# 中心主站原型执行单元（Execution Units）

## 使用边界

本执行单元集合依据：

- `docs/specifications/center-main-site-core.md`
- `docs/technical/center-main-site-core.md`
- 当前 `AGENTS.md` 与 `README.md`

形成。

单元按可观察业务结果纵向切分。具体源码路径、依赖精确版本、逐文件修改顺序和测试命令不在这里冻结，由各执行单元进入 Fresh Context 后通过即时计划（JIT Plan）确定。

---

## EU-01 栏目管理闭环

**goal**

建立可运行原型的最小前后端与数据库骨架，并完成后台栏目管理闭环，使栏目层级、排序、启停和基础删除约束能够通过真实界面与持久化行为验证。

**spec_reference**

- Specification 4.1 栏目结构维护
- Business Rule 3：栏目归属必须保持有效
- Boundary / Failure Behavior：存在下属栏目或内容时阻止直接删除
- Acceptance Criteria 1、2 中下属栏目依赖部分

**completion_condition**

- 原型前端、Spring Boot 后端和 MySQL 持久化能够在开发环境协同运行；
- 管理端可以新增、修改、排序、启停一级栏目及子栏目；
- 刷新或重新进入后数据仍从 MySQL 正确恢复；
- 对存在子栏目的栏目执行删除会被后端拒绝，并在管理端产生可理解反馈；
- 相关后端业务规则具有自动化验证证据。

**dependencies**

- 无。

**constraints**

- 后端保持一个 Spring Boot 模块化单体应用；
- 使用 Kotlin、Java 21、Gradle、MyBatis、MySQL；
- 管理端采用 Vue 3 + TypeScript + Vite + Vue Router + Element Plus；
- 不引入认证授权、MQ、Redis、MinIO；
- 栏目模块不得通过未来内容模块的 Mapper 或表形成跨模块直接依赖。

## EU-02 导航管理与公开入口

**goal**

完成导航条目的后台维护，并让启用的主导航、服务入口和网站导航能够在公开站点形成真实入口，停用条目不再公开展示。

**spec_reference**

- Specification 4.2 菜单与导航组织
- Specification 4.5 主站首页中导航与服务入口相关行为
- Boundary / Failure Behavior：停用导航不继续作为正常公开入口
- Acceptance Criteria 3、8 中导航相关部分

**completion_condition**

- 管理端可以维护导航名称、目标地址或目标栏目、位置/类别、排序和启停状态；
- 公开站点只展示启用条目，并按配置位置与顺序形成可点击入口；
- 本站栏目目标可以正确进入已有栏目路由；外部 URL 可以正确跳转；
- 后续文章详情地址可作为本站目标地址使用，不要求本 Unit 在文章能力尚未完成时提前构造文章业务；
- 停用条目后刷新公开页面不再显示该入口；
- 相关公开过滤和目标解析具有自动化验证证据。

**dependencies**

- EU-01：内部栏目导航需要已有栏目能力与公共前端骨架。

**constraints**

- 导航模块拥有自己的持久化映射；
- 公开查询通过 `/api/public/**`，管理写操作通过 `/api/admin/**`；
- 外部链接只负责导航，不扩展目标系统业务能力。

## EU-03 文章草稿与文件资源维护

**goal**

完成后台文章草稿维护及正文图片、封面、附件等资源上传，使文章能够以草稿状态完整保存、编辑和重新加载，同时补齐“栏目存在内容时不可直接删除”的真实内容依赖约束。

**spec_reference**

- Specification 4.3 本站文章维护
- Specification 4.4：新建文章首先形成草稿；编辑不自动改变状态
- Business Rules 1、2、3
- Boundary / Failure Behavior：栏目存在内容时阻止直接删除
- Acceptance Criteria 2 中内容依赖部分、4、5 中草稿部分、6

**completion_condition**

- 管理端可以创建文章并维护标题、栏目、富文本正文、来源、发布日期、封面、附件、推荐/置顶/排序等当前字段；
- 新文章保存后状态为草稿；
- 草稿可以编辑并再次保存，编辑不会自动发布；
- 正文图片、封面和附件写入本地文件存储，MySQL 保存资源元数据与文章关联；
- 服务端生成并控制存储键，不接受客户端物理路径作为直接文件定位依据；
- 当栏目已经存在文章时，直接删除该栏目会被后端拒绝；该检查通过模块接口完成，不由栏目模块直接访问内容模块 Mapper 或表；
- 草稿文章及其资源不会通过正常公开 API 成为公开内容；
- 核心草稿、资源关联、栏目内容依赖和状态不变规则具有自动化验证证据。

**dependencies**

- EU-01：文章必须归属有效栏目，并需要复用已有栏目删除业务边界。

**constraints**

- 文件内容使用本地文件系统，不引入 MinIO；
- 资源模块与内容模块通过明确接口协作；
- 当前不建设独立公共素材库；
- 当前不建设审核流或认证授权。

## EU-04 发布状态与三级公开页面闭环

**goal**

实现文章发布、撤回和重新发布，并让已发布内容贯通公开首页、栏目/二级页面和内容详情页面；草稿与已撤回内容不能作为正常公开内容出现。

**spec_reference**

- Specification 4.4 发布状态与公开可见性
- Specification 4.5 主站首页
- Specification 4.6 栏目/二级页面
- Specification 4.7 内容详情页面的核心内容展示与直接访问
- Business Rules 1、2、4、5
- Acceptance Criteria 5、6、7、8、9、10、12、15 中相关部分

**completion_condition**

- 管理端可以执行“草稿 → 已发布 → 已撤回 → 已发布”状态操作；
- 发布与撤回由后端统一执行业务校验和数据库事务；
- 已发布文章进入公开首页内容区域、对应栏目列表和独立详情地址；
- 栏目页显示栏目位置、已发布文章标题和发布日期，并支持分页；
- 详情页展示标题、来源、发布日期、正文与正文图片；
- 正文图片通过受控公开资源接口读取，且其公开可用性受所属文章发布状态约束；
- 草稿不通过公开查询暴露；已撤回文章从正常公开入口消失；
- 已撤回、已删除或不存在文章直接访问时显示统一不可用/不存在结果；
- 编辑已发布文章不会自动改变其发布状态；
- 一条自动化或可重复端到端证据能够证明发布前后公开可见性变化。

**dependencies**

- EU-01：栏目归属与公开栏目路由；
- EU-02：首页导航与公开入口骨架；
- EU-03：文章与资源基础维护。

**constraints**

- 公开内容过滤必须在后端 `/api/public/**` 执行；
- 不通过前端隐藏替代后端发布状态约束；
- 不引入 MQ、缓存或最终一致性机制；
- 首页推荐、置顶、排序不得改变文章发布状态。

## EU-05 详情增强、附件与浏览量

**goal**

补全内容详情的附件下载、链接复制、二维码和浏览量能力，并把附件访问纳入已经建立的公开资源状态边界。

**spec_reference**

- Specification 4.7 内容详情页面
- Specification 4.8 浏览量
- Boundary / Failure Behavior 中公开内容不可用规则
- Acceptance Criteria 10、11、13

**completion_condition**

- 已发布详情页可以展示并下载附件；
- 附件通过既有受控公开资源边界读取，而不是暴露整个上传目录；
- 与草稿或已撤回文章关联的附件不能通过正常公开资源接口绕过文章状态成为公开内容；
- 详情页可以复制当前稳定地址并展示对应二维码；
- 访问已发布详情能够以 MySQL 原子更新方式增加简单浏览量；
- 管理端可以查看文章当前累计浏览量；
- 附件公开边界与浏览量递增具有自动化验证证据。

**dependencies**

- EU-03：文章文件资源基础；
- EU-04：发布状态、公开详情页与受控公开图片资源边界。

**constraints**

- 浏览量不扩展为来源分析、用户画像或复杂统计；
- 不使用 Redis、MQ 或独立分析系统；
- 文件存储仍为本地文件系统，但访问必须经过资源模块业务边界。

## EU-06 公开站点响应式与基础搜索引擎友好

**goal**

使公开首页、栏目页和详情页在当前目标终端上形成可用的响应式体验，并补齐稳定直接访问、页面标题与摘要等基础搜索引擎友好能力。

**spec_reference**

- Relevant Non-functional Constraints 7.2 响应式适配
- 7.3 浏览器兼容
- 7.4 主站视觉边界
- 7.5 基础搜索引擎友好
- Acceptance Criteria 14、16

**completion_condition**

- 首页、栏目页和详情页在桌面、平板和手机主要视口下没有依赖固定桌面宽度才能使用的布局；
- 移动端导航可折叠，内容列表和图片能够适配可用宽度；
- 公开页面保持蓝—青色主题并具备一致信息层级；
- 公开详情和栏目地址支持浏览器刷新、前进后退和复制后直接访问；
- 页面根据当前内容设置合理标题和摘要信息；
- Vue Router 的服务端 fallback 在原型运行方式下可验证；
- 对当前重点浏览器至少形成可重复的主要页面 smoke verification；
- 对 SPA 基础收录风险形成当前证据，不在没有证据时扩展到 SSR/SSG。

**dependencies**

- EU-02：公开导航与首页入口；
- EU-04：三级公开页面；
- EU-05：完整详情体验。

**constraints**

- 当前保持 Vue 3 SPA，不预先引入 SSR / SSG 框架；
- 不要求 Internet Explorer；
- 不扩展复杂 SEO 运营、关键词管理或收录效果分析。

## Coverage Notes

- 栏目：EU-01，并在 EU-03 补齐“栏目已有内容时不可删除”的真实内容依赖；
- 导航与入口：EU-02；
- 文章草稿与资源维护：EU-03；
- 发布状态、首页、栏目页、详情核心闭环与正文图片公开边界：EU-04；
- 附件、复制/二维码、浏览量：EU-05；
- 响应式、浏览器与基础搜索引擎友好：EU-06。

当前 Out of Scope 的认证授权、党建主题、iframe、互动、全文搜索、复杂统计、多站点、历史迁移、MQ、Redis、MinIO、未来 `jilinjobs` 集成没有形成执行单元。
